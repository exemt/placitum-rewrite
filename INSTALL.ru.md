# Установка

[English](INSTALL.md) · Русский

Инспектор не слушает сеть: он подписчик очереди на шине. Адрес и сервис ему не нужны, и добавление
копии не трогает ни узел защиты, ни конфигурацию. Обычно его ставит `placitum-core`.

Стоит он на **фазе ответа**, и это определяет всё остальное: тело ответа до него не едет по шине, а
лежит в обменнике, куда его положил модуль.

## Что нужно рядом

| Компонент | Обязателен | Зачем |
| --- | --- | --- |
| NATS | да | очередь инспектора, аудит, журнал, поколение профилей |
| Redis: обменник | да | модуль кладёт туда тело ответа, инспектор читает его и кладёт переписанную копию под `<node>:<rid>:rsp:out` |
| Контроллер | да | шлёт профили поколением (канал `policy/rewrite`) |
| Отправители канала действий | нет | группы, выключенные по умолчанию, включаются их просьбой `mutate` |

Без обменника инспектору нечего править: тело ответа он получает только по локатору.

## Настройки

| Переменная | По умолчанию | Что задаёт |
| --- | --- | --- |
| `NATS_URL` | `nats://127.0.0.1:4222` | шина |
| `REDIS_URL` | из `inspector.conf` | обменник: тело ответа и переписанная копия |
| `WAF_REWRITE_SUBJECT` | `waf.req.rewrite` | подписка; должна совпадать с `subject=` в объявлении инспектора |
| `WAF_REWRITE_NAME` | `rewrite` | имя в реестре инспекторов и в кадре присутствия |
| `WAF_REWRITE_QUEUE` | имя | очередь шины: копии с одной очередью делят поток |
| `WAF_REWRITE_PROFILES` | `./profiles`; в образе `/app/profiles` | профили; поколение контроллера их перекрывает |
| `WAF_REWRITE_DATA` | `<профили>.applied`; в образе `/var/lib/waf/rewrite` | куда раскатка кладёт применённое поколение |
| `WAF_REWRITE_RELOAD_EVERY` | `1s` | как часто проверять каталог профилей |
| `WAF_REWRITE_WORKERS` | число ядер | воркеры очереди |
| `WAF_REWRITE_QUEUE_DEPTH`, `WAF_REWRITE_QUEUE_FULL`, `WAF_REWRITE_QUEUE_EXPAND` | `256`, `drop`, `off` | очередь и поведение при переполнении; то же через `inspector.conf` |
| `WAF_REWRITE_RESERVE_MS`, `WAF_REWRITE_MIN_BUDGET_MS` | `2`, `2` | запас до дедлайна и минимальный бюджет, при котором сообщение ещё берётся в работу |
| `WAF_REWRITE_VERSIONS` | `2` | версии схемы сообщения, которые процесс принимает |
| `WAF_REWRITE_CONF` | `inspector.conf` в рабочем каталоге, затем `/app/inspector.conf` | очередь и адреса Redis |
| `WAF_REWRITE_LOG` | `info` | стартовый уровень журнала; живьём его переставляет панель |
| `WAF_HEARTBEAT_EVERY` | `4s` | период кадра присутствия |
| `WAF_LOG_SHIP` | `on` | уезжает ли журнал процесса на шину; `off` оставляет только stdout |

## Docker Compose

```yaml
services:
  inspector-rewrite:
    image: placitum/rewrite
    scale: 2
    environment:
      NATS_URL: nats://nats:4222
      REDIS_URL: redis://redis:6379
      WAF_REWRITE_SUBJECT: waf.req.rewrite
      WAF_REWRITE_NAME: rewrite
    depends_on: [nats, redis]
```

## Проверка

Своего порта у инспектора нет, поэтому проверяют его тем же путём, что и работает, — сообщением по
шине. Проба в образе ходит с профилем `_probe`: группа с одной заголовочной операцией, и секция
`rewrite` в ответе приходит без Redis и без трафика.

```sh
docker exec <контейнер> rewrite-probe --quiet --timeout 1s --uri /healthcheck
```

`HEALTHCHECK` образа делает ровно это. В журнале при здоровом старте: подключение к шине, имя
очереди, загруженные профили, число воркеров.

## Грабли

- **Subject в двух местах.** `WAF_REWRITE_SUBJECT` у процесса и `subject=` в объявлении инспектора
  у модуля. Разойдутся — модуль ждёт ответа на один subject, инспектор слушает другой, и на каждом
  ответе срабатывает политика дедлайна.
- **Обменник у модуля и у инспектора — один и тот же.** Модуль кладёт тело в свой Redis; инспектор,
  читающий другой, отвечает, что объекта нет, и подмена не случается.
- **Регулярные выражения исполняются только здесь.** Их компилирует инспектор (RE2, линейное
  время), модуль их не видит. Тяжёлое выражение стоит времени ответа, а не памяти узла.
- **`"off"` в профиле — в кавычках.** YAML 1.1 читает голое `off` как `false`.
