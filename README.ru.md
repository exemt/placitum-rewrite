# Placitum rewrite

[English](README.md) · Русский

Инспектор правки ответов Placitum. Правит то, что уходит клиенту: удаление, замена и вставка по
регулярным выражениям в теле ответа плюс операции над заголовками. Стоит на фазе ответа. Профили —
группы модификаторов с условиями по коду ответа и типу содержимого, включённые по умолчанию либо
просьбой соседей (`mutate` или `skip` канала действий).

## Как это устроено

Байты не ездят по шине. Модуль в `waf_hold response gate` держит ответ и кладёт его тело в
обменник (Redis). Инспектор читает объект по локатору, применяет активные группы и кладёт
переписанную копию под ключ `<node>:<rid>:rsp:out`. В ответе едут адрес объекта, операции над
заголовками и имена применённых групп; модуль сверяет префикс ключа со своим запросом, поднимает
объект, подменяет удержанное тело, чинит `Content-Length` и отпускает ответ. Регулярные выражения
исполняются только здесь, движком RE2 из Go за линейное время: модуль выражения с провода не
компилирует.

## Профиль

```yaml
mode: enforce            # печатает контроллер; режим вызова задаётся на маршруте (waf_inspect … mode=).
                         # В файле observe считает правку, но отдаёт ответ нетронутым с
                         # REWRITE_OBSERVE; "off" пишут в кавычках (YAML 1.1)
deny_response: rewrite_failed   # запись каталога для отказа по несостоявшейся подмене

groups:
  - name: mask_pii
    default: false       # включается просьбой mutate
    status: [200]
    content_type: [application/json, +json]
    body:
      - { op: replace, pattern: '\b(\d{4})\d{8}(\d{4})\b', to: "$1********$2" }
      - { op: remove,  pattern: "debug-token=[a-z0-9]+" }
      - { op: insert_before, pattern: "</body>", text: "<!-- filtered -->", max_matches: 1 }
  - name: strip_server
    default: true
    headers:
      - { op: unset, name: Server }
      - { op: set, name: X-Frame-Options, value: DENY }

trigger:
  prior:
    - { from: action, accept: [mutate], codes: [PII_SUSPECT] }
    - { from: modsec, accept: [skip] }
```

Оба принимаемых глагола умеют ослаблять защиту, поэтому `from: "*"` не грузится.

Профили правят в панели: поколение контроллера перекрывает профили образа, а YAML выше — форма, в
которой поколение приезжает процессу. Правило приёма говорит, от кого и по какому поводу принимать
просьбы; какую группу переключить и куда, называет отправитель в самой просьбе (`group` и `set`).
Незнакомая группа даёт исход `unknown_group` в аудите.

`from` — имя декларации, а не процесса: два объявления одного процесса (`action`, `action-strict`)
для правил приёма — два разных отправителя, и каждому нужна своя строка.

Заголовочные запреты зеркалят модуль: `set Set-Cookie` нельзя (это канал cookie), `unset
Set-Cookie` можно; `set Content-Type` можно, `unset` — нет; `Content-Length` и прочей механикой
владеет модуль.

## Кадры WebSocket

После апгрейда модуль спрашивает инспектор на каждом кадре, если маршрут назвал его в
`waf_inspect frame:c2s|frame:s2c|frame`. Кадровые группы (`on: frame`) применяются к полезной
нагрузке кадра тем же путём: инспектор кладёт переписанную копию под `<node>:<rid>:frm:out`, а
модуль собирает кадр заново с тем же опкодом и fin (кадры клиента — с маской оригинала). Кадр за
кадром, без сборки фрагментов, поэтому выражение через границу фрагментов не совпадёт.

```yaml
groups:
  - name: ws_in                 # слово клиента маскируется до приложения
    default: true
    on: frame
    direction: [c2s]
    body:
      - { op: replace, pattern: "badword", to: "***" }
  - name: ws_out                # секрет приложения маскируется до клиента
    default: true
    on: frame
    direction: [s2c]
    opcode: [text]
    body:
      - { op: replace, pattern: "secret-[0-9]+", to: "secret-***" }
```

Условия кадровой группы — `direction` (`c2s`, `s2c`; пусто — обе) и `opcode` (`text`, `binary`,
`continuation`; пусто — только `text`). Кода ответа, типа и заголовочных операций у кадровой группы
нет, а ответные группы (`on: response`, умолчание) кадров не трогают. Просьбы `mutate` и `skip`
работают внутри кадра: сосед ранней волны включает группу для того же кадра. Если модуль не смог
поднять переписанный кадр, решает исключение направления (`waf_exception <направление> body`):
`deny` закрывает соединение, `pass` отдаёт оригинал. Маршрут обязан снимать полезную нагрузку
(`waf_capture frame body=`).

## Настройка маршрута

```jsonc
"capture":       ["request headers args body", "response headers body"],
"responseHold":  "gate",
"bodyLimit":     "response 4m",   "bodyLimitPolicy":        "pass",
"responseDeadlineMs": 3000,       "responseDeadlinePolicy": "pass",
"responseInspectors": [{ "name": "rewrite", "wave": 0, "timeoutMs": 2500 }]
```

- **Тело целиком и удержание ответа.** С `monitor` подмена не состоится: отпущенный ответ уже у
  клиента, в записи будет `applied: false`.
- **Предел тела ответа.** Умолчание модуля — `1m block`: как только фаза ответа включена, страница
  крупнее мегабайта уходит клиенту отказом.
- **Дедлайн фазы.** Умолчание — 50 мс, а полмегабайта надо прочитать из обменника, переписать и
  положить обратно. Политика `pass` сохраняет страницу, если правка опоздала.
- **Никаких соседей с `resume=require` на этой фазе**: фаза ждёт их до дедлайна, и ответ rewrite
  пропадает вместе с ней.
- **Сжатый ответ апстрима не правится**: снимок тела просит у апстрима `Accept-Encoding: identity`.
- **Архив и превью хранят оригинал**; расхождение помечено секцией `rewrite` в записи аудита.

## В аудите

Секция `rewrite` каждого участника доезжает до карточки инцидента, и панель печатает заметку вида
«правка ответа применена · mask, hdrs · 128B». `applied: false` — не пропуск: так выглядит
наблюдающий профиль и проигравший заказ (объект поднимают ровно один), и группы рядом отвечают на
вопрос «что было бы применено». Наблюдение файлового профиля (`mode: observe`) глушит только правку:
ответ уходит нетронутым с `REWRITE_OBSERVE` (или `REWRITE_NOOP`, если применять было нечего), в
событии `kind=inspector` — `engine.passive: true` и `would_apply`.

Проверка здоровья образа, `rewrite-probe`, идёт настоящим путём инспекции и проверяет, что профиль
`_probe` применил свою заголовочную группу, — без Redis и без трафика.

Что нужно рядом и все настройки — в [INSTALL.ru.md](INSTALL.ru.md).
